# BXAGI 广告工作台 2.2

通用广告工作台接入 **BXAGI 实际员工平台**（https://bxagi.xinlx.com/workforce）。目标流程为：BXAGI 登录 → 上传原始素材包并封存输入批次 → 在任务中心选择成品数量与员工并明确开始优化 → 实际成品归档 → 按素材包创建独立成品投放单元 → 投放员工检查 → 预算保护工具执行渠道操作 → 汇总真实效果并形成下一轮建议。

截至 2026-10-15 03:12 UTC，官方市场视频优化专家已实际生成新的22秒六镜头竖屏演示：720×1280、24fps、H.264与AAC音乐音轨。首版两处字卡重叠经过同一任务的一次排版修正，最终视频、封面和制作说明完整归档，独立解码与代表帧检查通过。此前10秒视频及PNG样张的验收记录继续保留。详见 [验证记录](docs/VERIFICATION.md)。这些样张不代表商业质量、全行业、付费投放或效果闭环已验收。

已有离线恢复能力：节点、网关、运行时故障与员工权益分开判断；保留原任务并退避重试，不重发已确认指令；节点心跳与状态变化按账号保存；视频、封面等部分成品可预览下载，完整交付检查在服务端保护投放。大管家初始化与真实派发仍需要可用的 BXAGI 节点。

后台固定调度入口和独立分钟执行器已实现，只有配置开启且近期实际成功心跳存在时才显示后台运行。当前演示站点尚未连接长期执行器；Cloudflare 部署授权和正式服务访问仍待接通，不能以本地测试或开关代替上线。见 [后台调度部署](docs/BACKGROUND_SCHEDULER.md)。产品用户只用 BXAGI 登录，调度器不依赖额外大模型。

## 八模块业务工作区

本轮按原方案落实 M1 原始素材管理、M2 任务中心、M3 优化素材中心、M4 投放中心、M5 数据中心、M6 经营决策、M7 系统管理、M8 进化中心。首页为工作区总览，员工与大管家配置归入 M2。

上传只保存原始资料，不自动派发。用户在 M2 配置 1–3 条主成品、图片或视频、比例及市场员工；M3 按批次展示实际交付；M4 按素材包管理共享额度，每条成品有独立投放状态、预算与效果。M5 提供整体汇总，M6 的已采纳素材建议进入 M2 等待明确执行，M8 沉淀提供参考的方法版本。渠道和后台尚未接通的能力仍明确显示实际状态。

模块职责、数据关系和验收边界详见 [八模块平台说明](docs/EIGHT_MODULE_PLATFORM.md)。

## 批量剧目准备

M2 新增「批量剧目准备」，工作台可直接进入 `#tasks?view=releases`。每批最多录入 100 个剧名、每剧规划 1–30 条成品，分别登记付费和免费推广链，关联当前账号的素材包，记录在架、授权、预算、优先级及失败原因。批次按 BXAGI 账号持久保存，修改带版本校验，避免覆盖其他窗口的更新；导出 CSV 对公式输入做转义。

素材数量来自已上传文件和可核实的完整主成品。只有所需资料与目标成品齐备、人工确认在架及授权、预算已填写且没有未解决失败，才显示「资料齐备」。这不代表已经投放。常读剧目列表已适配官方协议但账号未验证，推广链与创量接口尚未接入；本轮不自动创建推广链、下载剧目或提交广告。100 × 30 是规划容量，不是已验收的日生产能力。现有员工单次 1–3 条生产流程保留。

后端入口为 `/api/v2/release-batches`，通过专门服务管理 `jobs.type = release_batch` 记录；这些准备记录不进入员工调度和通用 bootstrap 任务列表，不改变既有业务数据结构。

## BXAGI 独立登录

应用只使用 BXAGI 账号与官方 `/api/auth/me` 确认的稳定账号 ID，不接受其他平台身份头或请求体用户 ID。未登录时显示 BXAGI 专属登录页，项目、文件、账户、预算、任务和效果 API 都返回登录要求。密码不保存，令牌在服务端加密。

`bxagiAccounts` 为稳定账号绑定工作区；`bxagiLegacyBindings` 保存旧版本已验证账号的关联证据。单一旧工作区保留原数据，多归属冲突返回 409，不按邮箱合并。

独立构建：`npm run build:standalone`。此构建不加载托管平台认证、connector 或 `.openai` 项目配置；可部署到自己的 Cloudflare Worker、D1 和 R2，见 [STANDALONE_DEPLOYMENT.md](docs/STANDALONE_DEPLOYMENT.md)。当前演示地址仍使用原托管基础设施，不代表已迁移到 BXAGI 官网服务器。

## 传输兼容修复

已修复部署运行时不接受 `redirect: error` 导致的登录请求即时失败。官方接口请求采用 `manual`，显式拒绝所有重定向，不把密码或令牌转交到其他地址。素材员工和渠道 HTTP 传输使用同一兼容策略。

服务健康查询可通过 `/api/v2/system/health?probeBxagi=true` 匿名探测官方 `/api/auth/config`；该操作不登录、不使用已保存凭证，也不执行员工任务。

## 实际实现

- BXAGI 用户名／手机号登录，随后用官方 `/api/auth/me` 核实身份；令牌在服务端加密，密码不保存。登录使用已注册的 BXAGI 账号，不创建账号或接受新的法律协议。
- 官方员工市场模板是唯一选人来源，按素材和目标匹配岗位；账号安装记录、激活状态、授权节点和原始员工会话只用于核验所选岗位是否可执行，不从历史调用反推员工目录。
- 未激活岗位明确等待。仅在显式开启 `BXAGI_MARKET_AUTO_ACTIVATE_FREE`、实时核实零费用 Solo 名额且无默认日程时，允许自动启用对应新岗位；安装结果不明不重试，不自动付费购买或续费。
- 独立员工会话复用已授权节点和记忆空间；先上传真实源文件和 brief，再派发实际指令。
- 生产会话显式关闭规划模式；原资源为 PlanAgent 时，先核实官方 CodeActAgent 可用再创建执行会话。实际会话若仍返回规划或只读模式，会在上传和派发前停止。
- 成品经专属任务清单与文件接口取得真实 PNG、MP4 或文案，保留来源、员工、会话和反馈版本。会话 READY、任务消息已提交或对话说“完成”都不等于成品已生成。
- 清单中的安全裸文件名仅在与 `filename` 精确一致、MIME 扩展名匹配时解析到当前任务 output 目录，不允许绝对路径、URL 或路径穿越。
- PNG 检查完整区块、CRC 和有界图像数据解压；MP4 检查完整容器、视频轨道及尺寸和时长元数据，保持 `fullDecode:false`。这些检查不自动保证 H.264、帧率、可播放性、运动或文字质量，也不代表广告效果改善；成品仍为草稿。
- 官方大管家可检查及免费初始化固定内置通用助理；其唯一标准每周反思按完整正文、固定配置字段与合法时间格式精确核验，允许作为内置记忆维护能力。其他含默认定时任务的市场模板仍不能自动安装；`standardBuiltinReflection:true` 不代表周报已执行。
- `general_mode` 仅控制官方通用聊天页面和内置卡片显示，大管家能力依据 `butler_mode` 检查。开启本站 `BXAGI_BUTLER_ENABLED` 后，协调阶段取得并核验市场岗位与生产步骤，再由现有员工工作流执行。初始化、调度和真实文件产出分别留证，未知派发不重试；派发接受或历史 completed 均不完成素材任务。具体策略见 [BXAGI 协议](docs/BXAGI_PROTOCOL.md)。
- 投放员工提交对应计划的执行请求后，由现有广告工具核实用户、素材和预算，执行实际渠道操作并读回。员工文本不能把计划改为 active。
- 真实效果可生成后续素材任务。数据不足、未知转化、需人补充信息或写入结果不明保持对应状态。重复派发有原子保护，结果不明不自动重试。
- D1/R2 保存用户自己的项目、文件、成品、预算、指标和任务；所有查找与下载按工作区用户隔离。广告凭据与 BXAGI 凭据均不会导出。

## 登录与运行边界

网页入口取消原托管账号门禁，用户只需 BXAGI 账号登录。公开入口不会公开工作区数据；所有资料仍经过 BXAGI 会话和账号归属校验。账号之间不按邮箱合并。

生产部署开启 `BXAGI_REQUIRED=true`。未登录 BXAGI 时不能查看工作区数据或执行任务。上游失败不会静默用本地规则冒充 BXAGI 员工。本地字幕/视频工具仍为独立辅助工具。

本站向员工转交的输入和收回的单个成果目前均限制为 **16 MiB**；云端原始文件存储上限仍为64 MiB。视频超过此范围需压缩或拆分。页面打开时会同步运行中的任务；页面关闭后的同步与预算监测需要实际持续运行后台执行器。

媒体下载默认 60 秒，显式上限 120 秒。受限原件下载在完整缓冲、声明长度及 MP4 顶层区块检查通过后返回，避免把截断流当作完整文件。此前视频诊断取得的 9,379,428 字节截断原件未作为成功交付；本轮已修复大文件回收完整性。

登录、市场、会话和文件协议来自 BXAGI 官方公开客户端。现场发现导出的 HTTP 消息路径返回 404 后，已接入官方 WebSocket 主通路，并取得真实 user MessageEvent 回执。真实 CodeActAgent 任务最终交付 `poster-v2.png`（1080×1080 RGB，56,929 字节）与 `notes-v2.txt`（1,994 字节），完成平台归档、授权下载、完整解码与中文可读性检查；首版不合格 PNG 保留为 rejected 历史记录。通用协议字段 `liveVerified: false` 不会因一次成功调用而改为全场景认证，单次实证单独记录。

当前真实广告连接为 0，未设置投放预算、未发生广告消费，尚未验证真实投放反馈闭环。云端协调模型与本地内嵌模型的 B/C 对比方案未部署；多行业质量、真实多用户并行运行和离页常驻执行仍需分别验收。

巨量引擎官方适配器已实现，需真实账户、接口权限、投放模板和转化数据。其他广告渠道尚未完成官方适配。总预算由报表与监测暂停控制，受渠道数据延迟影响，不是零超支保证。

## 快速剧库同步

入口为 **M1 原始素材管理 → 自动抓剧**，内容源在 **M7 系统管理 → 内容源** 配置。网页提交抓取任务后立即返回排队状态，查询直接读取独立索引剧库，抓取过程不占住列表。每页成功后保存进度，以来源、账号和剧目 ID 去重；暂停、换密钥与并发请求通过租约和版本保护，失败保留上次成功的数据。

常读作为业务上游，Vibbit 仅作产品参考。2026-10-21 已从官方公开文档元数据核实端原生短剧／漫剧列表和已有推广链接口；原始视频下载仍缺官方合同。具体取数路线及未接通项见 [CHANGDU_DATA_ACQUISITION.md](docs/CHANGDU_DATA_ACQUISITION.md)。内容源页面提供接入需求单，不包含用户凭据。

常读访问采用服务端签名 GET，凭据加密保存，保守维持全平台至多每秒一次请求。默认内置官方端原生列表协议：每页 100 条、创建时间降序、按 `total` 判断续页，并无损保存 i64 剧目编号。用户配置自己的 `distributor_id` 和 `secret_key` 后启动读取；首次成功响应才显示“读取已验证”。管理员可用 `CHANGDU_CATALOG_CONTRACT` 明确覆盖协议，非法配置会拒绝执行，不回退猜测。时间格式和付费／免费映射未经证实的字段保持空值／未知。

页面打开时可推进抓取；关闭页面后需要运行中的后台执行器。1–2 秒是已同步剧库查询的目标，不是全量同步、最新上游数据或视频文件下载的保证。本次新增能力只同步剧目元数据；没有接入真实常读账号前，不代表已经取得剧目、付费／免费推广链或视频。协议、部署配置与测试边界见 [CHANGDU_CATALOG.md](docs/CHANGDU_CATALOG.md)。

## 制作方案预设

M2 的素材优化支持高光精剪、开头对照和卖点对照方案。每条版本目标在提交前可预览；用户明确应用后，要求进入既有 `productionSpec.instructions`，由真实 BXAGI 员工执行并随任务冻结。自定义编辑与已采纳的经营建议保留各自含义，不将模板预览显示为已经完成的片段分析。现有每批 1–3 条、主成品数量和实际文件交付校验保持有效；未新增未经验证的大规模剪辑或自动质量评分能力。
