# BXAGI 通用广告平台架构 2.2

平台共用项目、素材、成品、预算和效果底座。服装、短剧、游戏及其他业务通过项目事实与实际员工能力进入同一流程；短剧是一个场景。2.1 的生产和投放任务接入 BXAGI 实际账号及其现有已雇佣员工，本地规则模板不代表远端员工执行。

## 目录与模块边界

本轮按页面入口、业务功能、状态、样式和服务端规则划分代码，保留原有接口、账号归属及实际业务执行边界。

| 路径 | 职责与约束 |
| --- | --- |
| `app/page.tsx`、`app/layout.tsx` | 应用入口与布局；页面入口组合登录状态、当前页面、项目选择和对话框，按已核实账号重建工作区视图状态 |
| `app/api/v2/[...path]/route.ts` | HTTP 路由入口，将请求交给服务端平台 API |
| `components/platform/workspace/` | `navigation.ts` 定义导航与页面说明；`workspace-shell.tsx` 提供工作区框架；`screens.tsx` 负责页面按需加载、加载提示和错误边界 |
| `components/platform/` | 保留各业务页面组合、共用 UI、类型、API 调用与自动同步 hooks，避免页面入口重复实现业务界面 |
| `features/account/` | 登录表单、提交状态及账号介绍；登录后的实际身份仍由服务端核实 |
| `features/projects/` | 新建项目、项目列表导航、原始素材和交付文件区域，以及 `use-project-files.ts` 的上传交互 |
| `features/library/` | 共享资源卡片、媒体类型及尺寸/时长展示和预览，供项目页面及素材库复用 |
| `styles/platform/` | 分离设计变量、基础、外壳、共用组件、工作台、项目、运营、账号、生产、响应式与无障碍规则；`app/globals.css` 负责按顺序引入，保留样式层叠关系 |
| `components/platform/client-state.mjs`、`use-platform.ts` | 与 React 渲染分离的客户端 store，以及通过 `useSyncExternalStore` 连接页面的 hook |
| `server/platform-api.mjs`、`server/platform/` | API 入口继续执行身份、租户、CSRF 和业务路由检查；模块分别承接协议解析与验证、上传、下载和指标建议 |
| `server/bxagi-orchestrator.mjs`、`server/bxagi/` | 协调器保留远端任务状态与执行；独立模块处理岗位排序、任务提示、成果结构/路径校验与回收资格规则 |

客户端 store 为读取和操作记录会话代次，旧账号请求或过期刷新不能覆盖当前账号数据。读取可合并并取消旧请求，用户操作同步互斥，自动推进与用户操作协调执行；退出或会话变更先清理旧状态。成功写入后的刷新失败单独提示，不把成功写入显示为需要重复提交。这里的互斥只管理当前客户端，服务端的账号隔离、原子任务和预算操作保护仍需独立执行。

`server/platform/protocol.mjs` 集中有界 JSON 解析、错误响应和字段检查；`uploads.mjs` 保持 64 MiB 存储上限、媒体头核验及流式失败清理；`downloads.mjs` 负责不含存储键的公开文件投影和私有 Range 响应；`metrics.mjs` 只返回建议。下载调用前仍在 API 入口通过用户范围查询取得文件记录，通用模块不选择租户，也不扩大授权。

`server/bxagi/employee-routing.mjs`、`task-prompts.mjs`、`artifact-validation.mjs` 和 `production-eligibility.mjs` 是可独立验证的规则模块，不负责网络派发或广告写入。回收资格只表示可以尝试读取；实际执行仍需重新核对账号、输入和真实成品。PNG/MP4 的结构校验也不等于完整解码、语义质量或业务效果验收。

## 身份与租户

应用使用 BXAGI 独立登录。用户 ID 由服务端验证的 BXAGI subject 与工作区唯一映射确定；项目、素材、成品、广告账户、投放计划、任务、效果和审计按这个工作区 ID 查询。其他平台身份头、邮箱和请求体 userId 都不能提供授权。匿名访问只能进入登录页，不能读取工作区或文件。

服务端调用 BXAGI 官方登录及 `/api/auth/me`，以核实的稳定账号 ID 唯一绑定工作区，不按邮箱合并。`bxagiAccounts` 保存稳定绑定，`bxagiLegacyBindings` 保留升级前关联；单一旧关联保留原数据，多关联冲突需处理而不自动合并。BXAGI 访问令牌及广告账户凭据使用服务端 AES-GCM 加密；密码不保存，公开响应和导出不包含令牌。浏览器只持有受 BXAGI 工作区范围约束的随机会话 Cookie。换绑 BXAGI 账号后，既有任务仍受原账号身份检查约束。

## 员工目录与生产任务

项目说明、事实和文件元数据用于场景判断；此步骤不声称已经理解图片或视频内容。实际员工从当前 BXAGI 账号可用的已雇佣目录中选择，依据岗位、描述和技能安排生产或投放工作。没有可用员工或缺少权限时明确阻塞，不虚构员工，不自动雇佣或续费。

原始文件先归档到 R2，D1 保存所属项目和来源记录。BXAGI 当前单件输入转交上限为 **16 MiB**；较大的既有素材需压缩或拆分后派发。生产任务采用项目内原子去重，在独立会话和任务目录中转交文件与真实业务说明，再提交工作指令。会话启动、指令送达和文字回复均不等同于素材完成。

成果归档要求当前任务的交付清单和实际文件。只有在专属输出目录内读到受限大小的真实 PNG、MP4 或纯文本，并通过文件结构及来源校验后，才保存为账号内成品。成品保留源素材、员工和反馈版本关系；技术校验不代表语义审核或效果提升。需要人工补充信息或确认的任务保留等待状态，通过 BXAGI 处理后再同步。

## 投放与预算

用户选择实际成品、设置预算并明确启动后，先派发 BXAGI 投放员工任务。员工交付的投放决策仍需通过本平台的用户、素材、预算、账户及渠道权限检查，然后由已接通的广告适配器执行。员工回复不能直接把本地计划标为已投放。

渠道写入分阶段保存状态；未知创建或提交结果进入待核对状态，不自动重复外部写入。渠道预算及状态变更需读回确认。效果快照按日期和来源更新，未知转化收入保持 ROI=null。总预算依赖真实累计报表及停止控制，存在报告和执行延迟，并非渠道原生硬限额。

## 反馈与后台执行

优化任务绑定所属项目、计划和真实效果快照。数据充分时提出可追溯的素材实验；未知转化或陈旧数据不产生 ROI 结论，汇总计划数据不被当作单个素材的效果归因。新成果实际归档后才完成生产任务，完成不代表实验已经证实有效。

启用 `autoOptimize` 的计划，其符合条件的待处理素材优化任务由 **bxagi-tick** 周期选入并派发到 BXAGI。此后台闭环需要实际运行执行器，不能仅凭配置密钥宣称持续运行。预算监测使用独立执行周期，作用于全部活跃计划；`autoOptimize` 控制 ROI 调整与素材迭代，不关闭预算保护。服务执行器使用独立 Bearer 密钥，；公开入口不要求额外托管登录，执行器仍需要专用服务密钥。

## 原本地工具与验收范围

原本地规则方案、浏览器排版和 FFmpeg 媒体工具保留为独立工具或历史工作流。BXAGI 必需模式下，它们不会自动替代失败的远端员工任务；上游不可用时保持记录可读并明确报告连接问题。云端 Worker 不内置 FFmpeg。

2.2 已实现账号连接、员工任务、成果归档、预算和反馈的接口与控制流程。受控接口测试不等同于真实账号验收；**真实登录、现有员工节点的实际执行与交付，以及真实付费投放仍需对应账号和权限验收**。协议与访问细节见 [BXAGI_INTEGRATION_CONTRACT.md](BXAGI_INTEGRATION_CONTRACT.md)。

本轮结构与 UI 整理的全量自动回归 **571/571 通过**，`tsc --noEmit` 通过。`Overview` 与 `WorkspaceShell` 在空账号、已有项目两种数据下静态渲染通过，3 项 UI 可访问性回归通过。本轮没有进行浏览器交互 QA，也没有重新执行真实投放。原有真实业务说明与验收证据不因模块拆分或自动测试通过而扩大。
