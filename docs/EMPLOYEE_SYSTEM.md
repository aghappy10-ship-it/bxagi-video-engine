# 素材与投放员工体系

平台不把短剧当作业务边界。素材员工依照业务证据和处理能力选择；投放员工同时依照业务、营销目标和投放渠道选择。服装、游戏、短剧和通用广告是默认员工档案，新增业务可注册任意场景名称，不需要修改固定场景枚举。

## 实际处理流程

1. 上传原始素材，项目记录标题、产品名称、描述、用户确认的事实和营销目标。
2. `inferScene` 根据上述文本及文件名进行规则分类，返回场景、启发式置信度和明确依据。该数值是规则证据强度，不是经统计校准的分类准确率。MIME 只标记格式；不通过 `.jpg` 或未知文件名猜测图片里的对象。多个场景冲突或缺少证据时使用通用素材员工。
3. `buildCreativePlan` 自动选择素材员工，生成主体展示、事实聚焦、详情引导三个草稿。每个草稿保留事实与素材来源，不生成未提供的价格、功效、游戏机制、剧情或收益承诺。
4. 图片用原始文件在浏览器 Canvas 中生成实际 PNG，提供竖版 1080×1920、方图 1080×1080、横版 1920×1080。默认完整适配图片，字体与文案绘制在版式中。生产记录的语义状态仍是草稿，等待用户审核。
5. 视频可调用已有浏览器视频引擎生成真实片段，必须明确起止时间。文件重新解码后返回实际尺寸/格式；不把文案草稿当作已生成视频。当前视频路径实际完成裁切、画幅适配和浏览器编码，尚不叠加生成文案；输出 `copyApplied: false`。云端 FFmpeg、自动语音识别、语义选段不在已配置能力中。
6. 用户审核素材后设置营销目标、渠道和预算，投放员工由这三个维度自动选择。员工选择不等于渠道授权完成，实际调用由服务端渠道适配器决定。

## 扩展新业务

员工档案包含 `id`、`name`、`role`、`scenes`、`keywords`、`objectives`、`channels`、`capabilities`、`instructions`、`version`。`role` 为 `production` 或 `buying`；场景名称不限定枚举。例如牙科、汽车或教育可注册新的生产档案和线索投放档案。

```js
const customProfiles = [
  { id: 'auto-production', name: '汽车素材员工', role: 'production', scene: 'automotive', keywords: ['汽车', 'car'], capabilities: ['copy.variants', 'image.layout'], instructions: '仅使用用户提供的配置与实拍，不生成性能承诺。' },
  { id: 'auto-tencent-leads', name: '汽车线索投放员工', role: 'buying', scene: 'automotive', objectives: ['lead'], channels: ['tencent'], capabilities: ['campaign.plan', 'budget.guardrails'] },
];
```

只有档案实际声明的处理能力会被允许。未声明图片版式能力时，该员工的图片生成状态为 `unsupported_capability`。未注册的业务仍能使用通用员工；不会被强制归类为短剧。档案中的用户指令是数据，不执行脚本或注入 HTML，也不被当作产品事实。

生产员工指令中的“简洁/简短”选择精简事实文案；“浅色/白底”或“蓝色主题/蓝底”改变实际图片主题。其他任意指令保留在员工档案与版式元数据中，不被解释为新业务事实或可执行脚本。每份图片草稿指定一个实际输入图片，多个上传图片会依次用于不同草稿，素材来源与实际文件输入对应。

## 模型能力边界

规则分类以 `engine: 'rules'` 标记。可选的 `classifyWithModel` 接收服务端配置的 HTTPS 接口、真实凭证与模型名称，并通过兼容 Chat Completions 接口分类元数据。没有配置时返回规则结果，不发出模型请求，不声称已调用模型。此接口不提供图片视觉理解；图片本身的语义识别需另行配置多模态模型与经过授权的素材读取。

## 真实反馈与素材迭代

服务端从同一用户、同一项目的优化任务和已存反馈记录构建 `optimizationContext`，再调用 `buildCreativePlan`。上下文包含 `taskId`、`reason`、`iteration`、`campaignSnapshot` 和 `metricSnapshot`；不能直接把浏览器传入的宣称当成反馈或创意归因。

实验提议须具备可追溯任务和指标 ID、明确来源、新鲜数据，并达到下列任一规则门槛：

- CTR：至少 1000 次曝光，点击次数为合法整数且不超过曝光；点击率按点击/曝光重算。0 点击仍可构成已观察到的 CTR 数据。
- ROI：明确存在转化收入，消耗至少 50、转化至少 3 次，收入为已确认的非负金额；ROI 按收入/消耗重算，不接受孤立的 ROI 宣称。

这些是首版实验策略门槛，未经统计显著性校准。缺少来源、数据陈旧、未知收入且曝光/点击不足时，返回 `optimization.status: 'collect_data'` 并说明继续收集数据，草稿不标记为效果实验。若收入未知但 CTR 数据充分，只提出 CTR 驱动的标题/版式实验，不推断 ROI。

充分数据返回 `experiment_ready`，以同一原始图片、同一画幅生成事实参考版、另一个已提供事实的标题版、视觉主题版，使一次实验只改动指定表达。没有更多事实可用于标题时，改用主题实验，不编造新卖点。反馈只用于选择实验方向，不进入广告功效或收益文案。每个草稿保留事实、素材和反馈来源。

每轮版本为 `taskId:r<iteration>`，草稿 ID 包含该版本，避免新旧版本混淆；重试同一轮次得到相同 ID，下一轮次得到不同 ID。草稿记录 `experiment.status: 'proposed'` 和 `requiresNewPerformanceData: true`，表示待投放验证，不表示已经提升效果。当前实际视频路径仍为裁切/适配/编码，标题与主题实验元数据不会被假装已经叠加到视频画面。视频反馈方案明确返回 `processing.supported: false`、`needs_external_video_production: true` 和对应原因，任务等待实际外部生产；普通视频裁切保持可用。禁止将相同原片的重复编码当成反馈优化成片。

计划汇总报表默认 `scope: 'campaign'`。即使计划包含某个素材 ID，也不能推断这个素材的成绩或宣称找到赢家。只有服务端提供明确、已核验的素材归因字段，且素材属于该计划，才允许 `scope: 'creative'`。手工导入报表保留 `manual` 来源，不标记为媒体 API 验证。

## 验证

`node --test tests/materials-engine.test.mjs` 验证三类默认分类、未知素材回退、冲突回退、任意新业务、目标与渠道路由、事实来源、能力限制、图片适配几何、无实际文件时失败、配置模型请求、数据不足保持收集、CTR/ROI 实验门槛、归因边界、版本 ID 和事实对照实验。浏览器实际像素导出需由集成验收覆盖。
